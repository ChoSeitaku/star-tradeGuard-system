# 电商风险控制系统 · 接口说明

- 服务地址：`http://127.0.0.1:8005`
- 接口前缀：`/api`
- 请求/响应编码：`UTF-8`，`Content-Type: application/json`
- 在线调试文档：`http://127.0.0.1:8005/docs`（Swagger UI，由 FastAPI 自动生成）

## 通用约定

### 枚举取值

| 类别 | 取值 | 中文含义 |
| --- | --- | --- |
| 业务事件 `event_type` | `order_create` | 下单 |
| | `order_pay` | 支付 |
| | `after_sale_apply` | 售后申请 |
| | `logistics_complaint` | 物流投诉 |
| 风险等级 `risk_level` | `low` / `medium` / `high` | 低 / 中 / 高 |
| 处理建议 `decision` | `pass` / `manual_review` / `reject` | 放行 / 人工审核 / 拒绝 |
| 案件状态 `case_status` | `pending` | 待审核 |
| | `reviewing` | 审核中 |
| | `approved` | 已通过 |
| | `rejected` | 已拒绝 |
| | `resolved` | 已结案 |
| 黑名单类型 `blacklist_type` | `user` / `order` / `address` / `ip` / `phone` | 用户 / 订单 / 收货地址 / 设备IP / 手机号 |
| 审核结论 `review_result` | `approve` / `reject` / `resolve` | 审核通过 / 审核拒绝 / 结案归档 |

### 评分模型

```
risk_score = min(100, Σ 命中规则分值)
risk_level = high    (score >= 70)
           | medium  (score >= 30)
           | low
decision   = reject        (high)
           | manual_review (medium)
           | pass          (low)
```

**自动建案规则**：当 `risk_level = high` 或 `decision ∈ {manual_review, reject}`（即 `score >= 30`）时自动创建案件：

- `decision = reject` → 案件状态 `reviewing`（审核中）
- `decision = manual_review` → 案件状态 `pending`（待审核）

### 案件状态流转

```
自动建案 ──┬─→ reviewing ──┐
           └─→ pending ────┴─→ review(approve) → approved ─┐
                             ├─→ review(reject)  → rejected ├─→ resolve → resolved
                             └─→ resolve                  ──┘
```

结案动作复用 `POST /api/risk/cases/review`（`review_result = resolve`），以保持接口集合与需求一致。

## 2. 检查模块

### POST /api/risk/check

发起一次风险检查。**每次检查都会完整保存**：原始入参（`risk_events`）、特征快照（`feature_snapshots`）、命中规则（`rule_hits`）与最终结果（`risk_assessments`）。

**请求体**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `event_type` | string | 是 | 业务事件类型，见枚举 |

## 3. 规则模块

`condition_json` 结构：

```json
{
  "all": [{ "op": "gte", "feature": "order_amount", "value": 5000 }],
  "any": [{ "op": "eq",  "feature": "order_status", "value": "已退款" }]
}
```

- `all`：全部命中才算命中（与）；`any`：任一命中即算命中（或）；两者同时存在时需同时满足
- 运算符：`gt` 大于 / `gte` 大于等于 / `lt` 小于 / `lte` 小于等于 / `eq` 等于 / `neq` 不等于 / `contains` 包含
- `contains` 为**列表成员判断**：`{"op":"contains","feature":"order_category","value":["虚拟卡券","数码3C"]}`
  表示该订单类目属于该列表
- 特征值为 `null`（数据缺失，如未支付订单的支付特征）时**一律判定为不命中**

### GET /api/risk/rules

查询规则列表。

| 查询参数 | 说明 |
| --- | --- |
| `keyword` | 模糊匹配规则名称 / 规则编码 |
| `rule_status` | `enabled` / `disabled` |

**响应**：`{ total, list[], operators[], features[] }`。`list` 每项包含
`id`、`rule_code`、`rule_name`、`rule_status`、`rule_status_label`、`priority`、`score`、
`condition_json`（原始字符串）、`condition`（已解析对象）、`description`、`updated_at`、`hit_count`（累计命中次数）。

### POST /api/risk/rules

新增规则。

```json
{
  "rule_code": "R_DEMO_TEMP",
  "rule_name": "演示临时规则",
  "rule_status": "enabled",
  "priority": 99,
  "score": 20,
  "condition_json": { "all": [{ "op": "gte", "feature": "order_amount", "value": 100 }] },
  "description": "演示创建"
}
```

**响应**：`{ "id": 25, "message": "规则创建成功" }`；规则编码重复返回 400。

### POST /api/risk/rules/update

更新规则，字段同上并追加 `id`。

**响应**：`{ "id": 25, "message": "规则更新成功" }`

### POST /api/risk/rules/status

启停用规则。停用后该规则**立即不参与**后续风险检查。

```json
{ "id": 1, "rule_status": "disabled" }
```

**响应**：`{ "id": 1, "rule_status": "disabled", "message": "规则【用户黑名单命中】已停用" }`

### POST /api/risk/rules/delete

删除规则。历史命中记录（`rule_hits`）**保留**作为留痕，其 `rule_id` 置空。

```json
{ "id": 25 }
```

**响应**：`{ "id": 25, "message": "规则【演示临时规则】已删除，历史命中记录保留" }`

## 5. 黑名单模块

黑名单在风险检查中**实时生效**：`user` / `address` / `ip` 三类直接参与特征计算，
因此增删黑名单会立即影响后续检查的评分。

### GET /api/risk/blacklists

| 查询参数 | 说明 |
| --- | --- |
| `page` / `page_size` | 分页 |
| `blacklist_type` | 类型过滤 |
| `status` | `active` / `disabled` |
| `keyword` | 模糊匹配命中值 / 备注 |

**响应**：`{ total, page, page_size, list[], type_stat{}, types[] }`

### POST /api/risk/blacklists

```json
{ "blacklist_type": "user", "blacklist_value": "U2001",
  "remark": "恶意刷单账号", "status": "active" }
```

**响应**：`{ "id": 5, "message": "黑名单新增成功：U2001" }`；重复条目返回 400。

### POST /api/risk/blacklists/delete

```json
{ "id": 5 }
```

**响应**：`{ "id": 5, "message": "黑名单已删除：U2001（后续风险检查将不再命中该条目）" }`

### POST /api/risk/blacklists/batch

批量导入，支持两种入参。

**方式一：文本（每行 `类型,命中值,备注`）**

```json
{ "text": "user,U2001,恶意刷单账号\nip,10.20.30.40,高风险设备IP\naddress,某某路1号,虚假地址" }
```

**方式二：结构化数组**

```json
{ "items": [{ "blacklist_type": "user", "blacklist_value": "U2001", "remark": "备注" }] }
```

**响应**

```json
{
  "success_count": 3, "skipped_count": 1,
  "skipped": ["user:U1001 - 黑名单已存在：用户 U1001"],
  "message": "批量导入完成：成功 3 条，跳过 1 条"
}
```

```json
  "case_status_stat": [{ "case_status": "pending", "label": "待审核", "count": 11 }],
  "rule_rank": [{ "rule_code": "R_BLACKLIST_IP", "rule_name": "设备IP黑名单",
                  "hit_count": 7, "total_score": 210, "ratio": 100.0 }],
  "blacklist_stat": {
    "total_hit": 13, "active_count": 3,
    "by_rule": [{ "rule_name": "设备IP黑名单", "hit_count": 7 }]
  },
  "trend": [{ "date": "2026-10-02", "total": 2, "high": 0, "medium": 2, "low": 0 }],
  "generated_at": "2026-10-08 14:30:00"

```

**指标口径**

| 指标 | 口径 |
| --- | --- |
| 风险事件总数 | `risk_events` 行数 |
| 高风险占比 | `risk_level='high'` 的评估数 / 评估总数 × 100% |
| 案件处理效率 | 已处理（`approved` + `rejected` + `resolved`）案件数 / 案件总数 × 100% |
| 平均处理时长 | 已审核案件 `updated_at - created_at` 的小时均值 |
| 规则命中排行 | `rule_hits` 按规则聚合，命中次数倒序取前 10 |
| 黑名单命中次数 | 命中 `rule_code LIKE 'R_BLACKLIST%'` 的记录总数 |
| 趋势 | 近 N 天按日聚合的评估量与风险等级分布 |

## 8. 错误响应格式

所有错误统一返回 FastAPI 标准结构：

```json
{ "detail": "错误描述" }
```

| 状态码 | 含义 |
| --- | --- |
| 400 | 入参校验失败（枚举非法、字段缺失、编码重复、案件已结案等） |
| 404 | 资源不存在（用户 / 订单 / 案件 / 评估 / 黑名单 / 规则） |
| 422 | 请求体结构不符合 Pydantic 模型定义 |
| 500 | 服务内部错误 |
